# Neon Zigzag

**[▶ Play in your browser](https://kayasibel.github.io/Neon-Zigzag/)**

An endless one-touch arcade game built in Unity 6 (URP). Tap to turn 90°, stay on the path,
and decide at every fork whether to play it safe or cut into the gem lane.

## The hook

The path periodically splits into a diamond that rejoins a few tiles later:

- **Cruise straight** — long, relaxed, no gems.
- **Snap-turn into the pink lane** — two taps in quick succession, but it is where the gems are.

Both branches merge at the same tile, so either choice stays playable. Gems drive a combo
multiplier during the run and bank into persistent currency that unlocks ball skins.

## Difficulty

The first 80 units of distance are a flat warm-up. After that, difficulty ramps over 650 units
on an exponential curve (`^1.4`), so pressure is back-loaded rather than immediate:

| | start | full |
|---|---|---|
| speed | 6 | 12.5 |
| straight length | 6 tiles | 3 tiles |
| fork frequency | 8% | 40% |

## Skins

Unlocked purely by lifetime gem milestones — no shop, no purchase step.

`PULSE` (0) → `EMBER` (40) → `TOXIC` (110) → `VOID` (240) → `FROST` (450) → `SOLAR` (800)

Tap the bottom strip on the title screen to switch between unlocked skins.

## Structure

The game builds its own scene at runtime, so any startup scene works and nothing needs wiring
up in the Inspector. There are no art or audio asset files: materials are generated by an
editor script into `Assets/Resources/Neon`, and sound effects are synthesised at runtime.

| Script | Responsibility |
|---|---|
| `GameBootstrap.cs` | Entry point; constructs the scene |
| `GameManager.cs` | State machine, score, combo, difficulty |
| `PathGenerator.cs` | Endless path and fork generation, pooling |
| `BallController.cs` | Movement, turning, coyote-turn forgiveness, falling |
| `CameraRig.cs` | Isometric follow camera, shake, post-processing |
| `HudUI.cs` | Runtime-built portrait HUD |
| `Progression.cs` / `SkinLibrary.cs` | Persistent gems and skin unlocks |
| `Sfx.cs` / `NeonFx.cs` | Procedural audio and particle bursts |

Movement is always `+X` or `+Z`, which makes `x + z` monotonically increasing. That single
value drives distance, scoring, tile recycling and generation lookahead.

## Building

Unity **6000.3.6f1**. Portrait orientation, designed for touch; mouse and space bar work in
the editor. Open the project and press Play — no scene setup required.

### WebGL

The `NeonPortrait` template locks the canvas to 9:16 and letterboxes it, so the portrait HUD
stays correct in a desktop browser. Unity's **decompression fallback** must stay enabled:
GitHub Pages serves static files without a `Content-Encoding` header, so a plain Brotli build
would never finish loading.

The published build lives on the `gh-pages` branch; `main` holds only the project.

## Status

Core loop, difficulty curve and progression are implemented and playable in the browser.
The HUD is laid out for portrait — the WebGL page letterboxes to suit it, but a native
landscape layout would still need work.
